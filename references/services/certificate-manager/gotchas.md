# Certificate Manager Gotchas

## Долго не выпускается или не перевыпускается сертификат

Симптом:
- сертификат долго остается в статусе `Pending`, `Validating` или `Renewing`;
- DNS-проверка прав на домен не завершается;
- пользователь утверждает, что запись уже добавлена, но статус не меняется.

Короткая гипотеза:
- чаще всего проблема в DNS-конфигурации `_acme-challenge.<domain>` или в смешении двух способов проверки: `CNAME` и `TXT`.

### Что важно помнить

1. Для DNS-проверки Certificate Manager нужно использовать только один тип записи:
   - либо `CNAME`;
   - либо `TXT`.
2. Если выбран способ через `CNAME`, на `_acme-challenge.<domain>` должна быть только запись `CNAME` на `<certificate-id>.cm.yandexcloud.net.`.
3. При `CNAME`-сценарии ожидаемый `TXT` должен отвечать уже на целевом имени `<certificate-id>.cm.yandexcloud.net.`, а не в DNS-зоне пользователя.
4. `dig ... TXT +short` может показать две строки:
   - первая строка — это `CNAME target`;
   - вторая строка — это `TXT` на целевом имени.
   Это нормальный формат для краткого вывода и не означает, что обе строки являются `TXT`.
5. Сам по себе набор из нескольких `TXT` не всегда ошибка. Ошибка — это наличие собственных `TXT` на `_acme-challenge.<domain>` одновременно с `CNAME` на этом же имени.

### Минимальная диагностика

1. Узнать авторитативные NS домена:
   - `dig +short NS <domain>`
2. Проверить `CNAME` именно у авторитативных NS:
   - `dig +noall +answer _acme-challenge.<domain> CNAME @<authoritative-ns>`
3. Проверить `TXT` именно у авторитативных NS:
   - `dig +noall +answer _acme-challenge.<domain> TXT @<authoritative-ns>`
4. Если есть `CNAME`, отдельно проверить `TXT` уже на target-имени:
   - `dig +noall +answer <certificate-id>.cm.yandexcloud.net TXT @1.1.1.1`

### Как интерпретировать результат

- Норма для `CNAME`-сценария:
  - `_acme-challenge.<domain>` возвращает только `CNAME`;
  - `<certificate-id>.cm.yandexcloud.net` возвращает ожидаемый `TXT`.
- Норма для `TXT`-сценария:
  - `_acme-challenge.<domain>` возвращает ожидаемый `TXT`;
  - `CNAME` на этом имени отсутствует.
- Ошибка:
  - `_acme-challenge.<domain>` возвращает и `CNAME`, и собственные `TXT`;
  - опубликован не тот `TXT`, который требует Certificate Manager;
  - проверка делалась только через рекурсивный резолвер, без сверки с авторитативными NS.

### Что рекомендовать

- Если выбран способ через `CNAME`:
  - удалить `TXT` на `_acme-challenge.<domain>`;
  - оставить только `CNAME`, который выдал Certificate Manager.
- Если выбран способ через `TXT`:
  - удалить `CNAME`;
  - оставить только требуемый `TXT`.
- После правки DNS:
  - дождаться обновления по TTL;
  - повторно проверить авторитативные NS;
  - если запись уже корректно видна у авторитативных NS, дальше обычно остается дождаться следующего цикла проверки со стороны Certificate Manager.
